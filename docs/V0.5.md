# v0.5 upgrade and evaluation guide

This branch prepares **0.5.0**; it does not publish a release. The latest released
version remains 0.4.0 until a maintainer explicitly approves publication.

## Upgrade compatibility

- RRF is still the default for both SDK and HTTP search. Existing calls and
  response shapes are unchanged. Score fusion must be requested explicitly.
- There is no database schema change from 0.4.0 and no reindex is required for
  a fusion-mode change. Model/provider/revision changes still require reindex.
- Back up and verify restoration before upgrading. Stop old service processes
  before switching versions. A rollback to 0.4.0 can read the same database, but
  callers must stop sending the new `fusion` / `lexical_weight` options.
- Databases predating 0.4.0 still need the explicit identity-adoption or reindex
  process in [the v0.4 guide](V0.4.md). This release does not relax that check.
- Logical tenant filtering prevents returning another tenant's documents. The
  database, resources and FTS5 BM25 collection statistics are shared: another
  tenant's writes can affect keyword ranks and therefore fused ranks. This is
  not physical, performance or ranking isolation. Applications needing those
  guarantees require separate indexes/databases and an appropriate access layer.

## Opt-in retrieval

```python
rag.search(key, query)  # Unchanged RRF default.
rag.search(key, query, fusion="score", lexical_weight=0.2)
rag.search(key, query, fusion="score", lexical_weight=0)  # Vector-only.
```

Scores are ranking signals, not confidence or probability. A keyword bonus can
hurt intent, exact-code, negation and numeric queries. Neither mode enforces
numeric filters or checks whether a generated answer satisfies a constraint.
Use application-side typed constraints and evaluate representative queries.
See [fusion evidence and limitations](FUSION.md).

## Long documents

`index()` embeds the document as one input; it does not chunk automatically.
The example multilingual MiniLM snapshot accepts 128 tokens, so its encoder can
truncate longer inputs. A keyword hit can still refer to text outside the
embedded prefix. Character chunk limits are not tokenizer limits.

Use `ingest()` / `ingest_batch()` for explicit deterministic chunks, choose
limits for the actual tokenizer, and audit truncation. Returned hits are chunks,
not deduplicated parent documents. Preserve `_chunk` source offsets for display
and apply a documented parent aggregation policy if your application needs it.
Do not compare parent and chunk recall as though they were the same metric.

## Optional local evaluation environment

The core library still has no third-party runtime dependencies. The local model
adapter is an evaluation extra, not a production model-serving component. Its
supported snapshot layout is a standalone Transformer + Pooling, optionally
Normalize, with safetensors, local files and no dynamic model code or prompts.

Use only trusted, immutable model snapshots and retain the file SHA-256 manifest.
Dependency and model license obligations remain separate from this project's
MIT license. We distribute neither model weights nor a bundled environment.
The source-pinned evaluation lock and current advisory results are recorded in
the release evidence; a successful model run on one Python/runtime does not
validate the optional stack across the whole core CI matrix.

Local loading is fail-closed but not a security sandbox. Do not give an
untrusted party write access to the model directory during validation/loading.
OS network isolation is stronger than Python offline flags or socket guards.
