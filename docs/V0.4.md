# v0.4 upgrade and ingestion guide

Version 0.4.0 adds the features below. The previous v0.3.0 wheel does not
contain them. This is a GitHub distribution, not a PyPI publication or production
deployment. No real-model quality result is claimed.

## Model identity and upgrading an existing database

Stop all v0.3 processes before opening a database with this branch. Old clients
and direct `Store` writes bypass the new identity and parent-lifecycle checks;
never run mixed application versions against the same database. Use `TenantRAG`
for normal operations. Back up and verify restoration before upgrading.

The database pins one descriptor (`provider`, `model`, `revision`) plus the
observed vector dimension. FakeEmbedder declares a versioned lexical algorithm;
OpenAIEmbedder uses its configured endpoint URL, model and `revision` (default
`unspecified`). API keys are not part of the descriptor. A same-dimension model
change is still rejected. Instantiation performs no provider calls, and an empty
database binds its dimension on the first successful write. Identity conflicts
are checked before provider I/O and again when using or committing the result.

Use an immutable model revision when possible. `unspecified` and mutable hosted
model aliases **cannot detect a provider changing weights behind the same
endpoint/model label**. Changing a revision label requires reindexing just like
changing models. Custom embedders must declare an `embedding_identity` dictionary
or pass an explicit `embedding_identity={"provider": ..., "model": ...,
"revision": ...}` to `TenantRAG` and to `reindex` when appropriate. These values
are operator declarations, not cryptographic model attestations.

Old databases lack provenance. Opening them preserves the data, but indexing,
ingestion and vector/hybrid search are blocked until a trusted operator chooses:

- **Known provenance:** configure the exact original model and call
  `rag.adopt_legacy_embeddings()`. This asserts that all existing vectors came
  from that model. It checks vector shape/values and known dimensions without
  calling the provider, but cannot prove their origin. Never adopt merely because
  dimensions match. Missing/malformed or mixed-dimension vectors require reindex.
- **Unknown provenance or a changed model:** call `rag.reindex(target_embedder)`
  to regenerate all stored retrieval vectors, across **every tenant**. This is a
  trusted database-owner Python operation, intentionally unavailable over HTTP.

Listing, usage and deletion remain available without adoption. Backups may
contain personal text and tenant authentication hashes; protect them accordingly.

### Backup and reindex cookbook

1. Stop old servers and prevent administrative/direct database writes. Make an
   SQLite backup and test it on a separate restored copy. For example, with the
   application stopped:

   ```python
   import sqlite3
   source = sqlite3.connect("tenantrag.db")
   backup = sqlite3.connect("tenantrag-before-v04.db")  # Choose a fresh filename.
   try:
       source.backup(backup)
       assert backup.execute("PRAGMA integrity_check").fetchone()[0] == "ok"
   finally:
       backup.close()
       source.close()
   ```

   Integrity checking is not a substitute for testing restored application data.
   Do not copy only the live `.db` file in WAL mode.

2. Configure the target model and explicitly rebuild. The following uses the
   offline lexical embedder, so it makes no network requests:

   ```python
   from tenantrag import TenantRAG
   from tenantrag.embed import FakeEmbedder

   with TenantRAG("tenantrag.db") as rag:
       count = rag.reindex(FakeEmbedder(), batch_size=64)
       print("Rebuilt retrieval vectors:", count)
       print(rag.identity.status())
   ```

   For a real model, pass `OpenAIEmbedder(api_key=..., base_url=..., model=...,
   revision="immutable-model-revision")` instead, only after approving the data
   transmission and potential provider cost. Set matching `EMBED_REVISION` or
   `--embed-revision` when restarting the HTTP server.

3. Reopen all service instances with the same descriptor. Verify representative
   searches, parent counts, isolation and restoration procedures before resuming
   normal service. Existing instances configured for the old model fail closed.

Reindex prepares vectors outside the write transaction, then checks that the
corpus and saved identity still match its snapshot. Concurrent changes reject
the attempt instead of overwriting new data. All vectors and identity switch in
one SQLite transaction. Provider failure, cancellation or interruption before
commit leaves the old index intact. `cancelled` can be a no-argument callback
returning true; it is checked between batches and before commit, not during a
blocking provider request. Retry starts from scratch, **not a durable resume**,
and can repeat billable work. If the caller loses contact around commit, reopen
and inspect `rag.identity.status()` before deciding to retry. Empty databases
have nothing to adopt/reindex. Preparation retains the snapshot and replacement
vectors in memory; it is designed for personal-scale corpora, not huge indexes.

## Text and Markdown ingestion

`index(key, text, doc_id=..., metadata=...)` remains the one-document operation
and does not silently start chunking. Use the explicit ingestion APIs:

```python
with TenantRAG("tenantrag.db") as rag:
    result = rag.ingest(
        key, "# Handbook\n\n" + "A long passage. " * 200,
        doc_id="handbook", source="handbook.md", format="markdown",
        metadata={"category": "internal"}, max_chars=1000, overlap=100,
    )
    print(result)  # doc_id, chunks, content_hash, unchanged
    results = rag.ingest_batch(key, [
        {"doc_id": "notes", "text": "Meeting notes", "source": "notes.txt"},
        {"doc_id": "policy", "text": "# Policy\n\nRules", "format": "markdown"},
    ], max_chars=1000, overlap=100, batch_size=64)
```

`key` must be an already registered tenant key. Batch documents can include
`text`, `doc_id`, `metadata`, `source` and `format`; chunk options are shared by
the batch. Duplicate parent IDs within one batch are rejected. Supply stable IDs
for idempotent updates: omitted IDs generate a new parent each time.

- Chunking is deterministic and preserves exact source text. Offsets are
  half-open Python Unicode character indexes: `original[start:end]` equals the
  chunk. They are **not bytes, tokens or grapheme clusters**. Text is not
  normalized. The chunker covers every source character; ingestion omits whitespace-only
  retrieval chunks while retaining the complete original parent text. Retained
  offsets still refer to the exact original source. Adjacent raw chunks overlap.
- Text prefers paragraph/newline boundaries. Markdown additionally prefers ATX
  headings outside fenced code. Oversized blocks can split at the character
  limit. It is not a Markdown renderer or full syntax parser; code fences and
  formatting need not remain intact in a chunk. Character limits are not provider
  token limits. No PDF, HTML conversion, OCR or file download is included.
  Input is capped at 1,000,000 Unicode characters per document. Chunking is
  capped at 10,000 chunks and 10,000,000 copied chunk characters per document;
  ingestion also caps the batch at 10,000 chunks and 10,000,000 chunk characters.
  Large overlaps may hit these bounds even for shorter input.
  Ingestion also limits JSON-encoded UTF-8 metadata to 65,536 bytes, source to
  16,384 bytes and document ID to 4,096 bytes. A conservative 10,000,000-byte
  per-batch budget bounds repeated chunk metadata/provenance, including source
  and parent ID. These additional limits apply to ingestion, not the original
  `index` API.
- Search returns retrieval chunks, each with a generated `doc_id` and
  `metadata._chunk` containing `parent_id`, `source`, `start`, `end`, `index`.
  `_chunk` is reserved; do not put application metadata under that key. Search is
  not parent-grouped and may return overlapping chunks from one parent.
- Listing returns original parent text/metadata, not individual chunks. Quota
  and usage count each parent once, plus each ordinary `index` document once.
  Replacing a parent is allowed at its quota limit. Chunk count, stored bytes and
  provider token cost have no separate quota; enforce application limits.
- Re-ingesting a parent atomically removes all obsolete chunks and installs its
  replacements. `delete(key, parent_id)` removes the parent and every chunk/FTS
  entry. Direct chunk update/delete is rejected; use the parent ID from `_chunk`.
  `index` with a parent ID converts it back to a single document; `ingest` with an
  ordinary document ID converts it to a parent, without charging another slot.
- The content hash covers text, metadata, source, format and chunk options. An
  identical stable-ID retry skips writes and embedding requests. Changed parents
  reuse exact text vectors already present **within the same tenant/model**;
  repeated new chunk text in a batch is embedded once. Different tenants do not
  share this cache. This is incremental embedding reuse, not removal of duplicate
  parent documents or a permanent embedding cache.
- Batch commit is all-or-nothing, including quota enforcement, parent rows,
  chunks and FTS. Provider preparation can happen before a quota/conflict error,
  so failure is not a promise of zero provider cost. Concurrent tenant changes
  reject the prepared batch; retry from fresh state. There is no partial-success
  response or automatic provider retry.

### HTTP additions

Both routes use the existing Bearer authentication, metering, request-size limit
and rate policy. Model adoption/reindex remain trusted Python-only operations.

```text
POST /v1/ingest
{"text":"# Guide\n\nDetails", "doc_id":"guide", "source":"guide.md",
 "format":"markdown", "max_chars":1000, "overlap":100}

POST /v1/ingest/batch
{"documents":[{"doc_id":"a","text":"First"},{"doc_id":"b","text":"Second"}],
 "max_chars":1000,"overlap":100}
```

Single ingestion returns `doc_id`, `chunks`, `content_hash`, `unchanged`; batch
returns `{"documents": [...]}`. HTTP does not expose the Python provider
`batch_size` option. Identity mismatch returns `409 embedding_identity_conflict`; concurrent tenant
changes return `409 ingestion_conflict` and require a fresh retry.
The local admin uploader retains its original single-document indexing behavior.
